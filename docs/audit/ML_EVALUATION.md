## Ranking paths

| Path | Implemented scoring and limitations |
|---|---|
| Live partner search | app.py (`128b152:backend/app.py:29`) filters a single stored candidate score by username exclusion, location and domain. Two different synthetic usernames produced identical lists with the same filters. Blank and unknown usernames have no explicit cold-start branch, and case variants can defeat exact self-exclusion. |
| Content experiment | [Content notebook](../../notebooks/modeling_content_based.ipynb), cells 3–9, deduplicates usernames, concatenates language and repository strings, fits English-stopword TF-IDF and computes cosine. There is no separate weight for language versus repository fields. Tokenization can lose meaningful short or punctuated names. |
| Activity experiment | [Collaborative notebook](../../notebooks/modeling_collaborative_filtering.ipynb), cells 1 and 4, uses cosine on min-max-scaled Followers, Following and Public_Repos. These are aggregate profile attributes. The serving pipeline does not learn from user-item interactions or observed collaboration. The five-row artifact consumed by the hybrid generator is a sample query's top list. |
| Notebook hybrid | [Early hybrid](../../notebooks/modeling_hybrid.ipynb), cell 1, blends content, activity and bio TF-IDF at 0.4/0.4/0.2. [Later hybrid](../../notebooks/modeling_hybrid_improvements.ipynb), cell 1, blends content, activity, bio TF-IDF and semantic at 0.4/0.3/0.1/0.2 with absent scores filled with zero. It joins on candidate username and reduces semantic neighbors to maximum score across targets, discarding pair identity. The checked-in content CSV already uses `content_score`, whereas the notebook attempts a legacy `score` rename. That rename is harmless with the current artifact, but source and artifact schema conventions differ. |
| Live semantic search | app.py (`128b152:backend/app.py:67`) embeds a free-text query and uses cosine against stored vectors. `[1:6]` drops the best candidate without a query identity, and results are not deduplicated. [Embedding producer](../../notebooks/compute_bio_embeddings.ipynb), cell 1, writes a matrix and matching CSV by row order. [Semantic experiment](../../notebooks/recommend_%20bio_semantic.ipynb), cells 2–6, instead filters missing/placeholder bios and exports target/candidate pairs. |
| Unwired prototype | [engine.py](../../backend/engine.py#L161) scores known usernames with 0.45 content, 0.35 activity and 0.20 embedding cosine. It builds sparse content features once and uses normalized dot products for activity and bio. Unknown users rank by equal parts followers and repo values from a pre-scaled CSV, with constant displayed component scores. This favors a popularity/activity proxy by construction. Generic explanation strings can assert high interaction similarity without checking the contribution. Missing embeddings silently zero the bio term and lexical fallback refits the corpus for each request. Weights are defaults without empirical support. |

## Data and ranking checks

- All 13 CSVs plus the NPY total 25,677,306 bytes. Cleaned and embedding profiles each have 4,104 rows and 3,890 case-folded unique usernames. Both tables currently agree on username order and bio text, and the NPY is finite float32 with shape 4,104 × 384. This verifies shape and CSV correspondence. The vector-to-profile mapping still relies on a producer invariant without an ID/hash manifest.
- The live score CSV has 4,106 rows for 3,890 identities, 800 distinct stored score strings and 434 zero-score rows. The HDBSCAN merge expanded to 4,536 rows before filters in the probe. Live partner search drops duplicate usernames before sorting, so join order selects the representative. Add canonical identity, deterministic tie-breaking and deduplication before serving top-k. Mask self by ID when a query has an identity. Preserve the best match for anonymous free text.
- HDBSCAN labels 3,564 of 4,104 rows `DevOps & Scripting`. DBSCAN assigns the same tag to 3,188 rows. These are artifact frequencies, not measured exposure or clustering quality. Neither route reranks for diversity. Popularity concentration in served lists has not been measured. Numeric scores are similarity signals or blends, with no probability calibration.
- Dense notebook cosine matrices cost O(N²), about 128 MiB each at 4,104 rows in float64. The live partner path copies and sorts candidates per request. Bio search constructs the corpus tensor and does exact O(Nd) scoring plus a full sort. Start with measured startup, RSS, and p50/p95 per endpoint on the current corpus and a scaled fixture. Try cached normalized vectors, prevalidated joins and bounded top-k before considering approximate search.

## Evaluation protocol

1. Define relevance as a useful prospective collaborator for a specific project brief. Build a consented or appropriately sourced set of blinded human judgments with a simple graded rubric and adjudication. Pool candidates from multiple baselines, include diverse negatives and report judgment coverage. Temporal collaboration outcomes can be an additional proxy if collected with appropriate permissions. Shared languages or current similarity scores are circular labels.
2. Use a fixed eligible candidate pool and filters per query. Split by query identity for user-level judgments, and by time when using historical outcomes. Keep future activity, labels and duplicates out of feature fitting and tuning. Define cohorts for known/unknown identity, sparse or missing bios, region, language, popularity and filters. Validate on one split, then compare once on a frozen test set.
3. Compare current static order, random and activity baselines, content-only, bio TF-IDF, Sentence-BERT, activity-only and the query-specific blend. Ablate each component and tune weights on validation data. Use the same candidate rules for every model. Evaluate unknown users with explicit project interests or languages when available. Measure the no-signal fallback separately.
4. Report macro Precision@K (relevant returned / K, with short lists counted as misses), Recall@K (relevant returned / known relevant eligible candidates), MAP@K (average across queries of precision at each relevant rank divided by min(K, number of known positives)), and NDCG@K (graded discounted gain divided by ideal gain). Use K=5 as the serving target, with K=1 and 10 for diagnosis. Report queries with zero known positives separately, document treatment of unjudged items and qualify recall as pooled recall if judgments are incomplete. Report paired bootstrap confidence intervals over queries.
5. Report duplicate/self-hit and empty-result rates, catalog coverage, intra-list diversity, exposure by follower band and candidate cohorts, and per-cohort ranking metrics. Audit explanations against actual score contributions. Track latency, memory and operational failures separately. Ship a ranking change only after agreeing on acceptance thresholds and demonstrating the trade-off against baselines.

Precision@K, Recall@K, MAP@K and NDCG@K are **unmeasured**. Notebook neighbor scores and cluster experiments are diagnostics. No relevance or diversity gain has been established.
